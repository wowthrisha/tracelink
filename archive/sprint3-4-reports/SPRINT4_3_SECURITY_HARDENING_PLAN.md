## Known Security Surface (from SECURITY_BASELINE.md + extraction audit)

### DRM protections (in useViewerSession.js)
- Right-click blocking: `document.addEventListener('contextmenu', ...)` when `can_right_click: false`
- Keyboard DRM: Ctrl+P, Ctrl+S, Ctrl+C, Ctrl+A, Ctrl+X, Ctrl+U blocked when permissions disallow
- Print interception: `beforeprint` / `afterprint` hide `.viewer-page` when `can_print: false`
- Tab blur: `blur` / `focus` / `visibilitychange` events blur page when tab is hidden

### Session security (in useViewerSession.js)
- Link token in sessionStorage (not localStorage) — scoped to tab, cleared on tab close
- 401 recovery: sessionStorage cleared → re-authenticate → setPage(1)
- Gate validation: password/email required before session established

### Content security
- `onContextMenu={e => e.preventDefault()}` on page container and per-page element
- `userSelect: session?.permissions?.can_copy ? 'text' : 'none'` on text docs
- `WebkitUserSelect` / `WebkitTouchCallout` on image elements
- `draggable={false}` on page images

### Annotation security
- `can_annotate` check gates all annotation API calls and AnnotationLayer rendering

### React CDN risk (R-063 / R-065)
- **RESOLVED** — React 18.3.1 is already pinned in `SecureDoc.html` with SRI hash (`sha384-...`). No action needed.

## Phase 2 — DRM Hardening Audit

Current DRM protections are in `useViewerSession.js`. They are event-listener based, which is correct for the browser environment. This phase verifies they cannot be bypassed by a determined user.

**Known limitations of browser-side DRM (document, do not "fix"):**
- A user can open DevTools and remove event listeners — this is inherent to all browser-side DRM
- Screenshots are not preventable in browsers
- `userSelect: none` can be overridden in DevTools

**Audit targets:**
1. Verify `can_print: false` path: `beforeprint` fires synchronously before print dialog
2. Verify `can_copy: false`: both `Ctrl+C` block AND CSS `user-select: none` are applied
3. Verify `can_right_click: false`: `contextmenu` preventDefault fires on document (not just on page element)
4. Verify blur on tab switch: `visibilitychange` fires and blur overlay appears
5. Verify `WebkitUserSelect: 'none'` is on image elements (not just text docs)
6. Verify `logEvent` is called for all blocked actions (audit trail completeness)

Generate: findings in `docs/security/SECURITY_HARDENING_AUDIT.md`

## Phase 3 — Session Token Audit

`link_token` flows through the entire viewer lifecycle. Verify:

1. `link_token` is stored in `sessionStorage` only — never in `localStorage`, never in the URL after initial load
2. All API calls that use `link_token` go through HTTPS (backend enforcement, but confirm no `http://` hardcoded in frontend)
3. `link_token` is NOT logged to console anywhere in the hooks
4. `session_id` is rotated correctly on 401 recovery (new session = new session_id)
5. `pendingToken` in useViewerSession — confirm it's never persisted across page loads (it's useState, so it's session-only)

## Phase 4 — Input Sanitization Audit

The viewer receives several user-controlled or server-controlled string values that are rendered to the DOM. Verify none can cause XSS:

| Value | Source | Rendered as | Risk |
|---|---|---|---|
| `docName` | Server API response | string in ViewerToolbar | Low (not innerHTML) |
| `session.watermark_text` | Server API response | CSS text content | None (not innerHTML) |
| `e.viewer_email` | Server API response | string in AccessLog table cells | Low (not innerHTML) |
| `e.event_type` | Server API response | string with `.replace()` | Low |
| `threadView.root.comment_text` | Server API response | string in div | None if not innerHTML |
| `textContent` | Server API response (text doc chunks) | `<pre>` text content | Safe (pre element, not innerHTML) |
| `link.url` | Server API response | `href` attribute and `title` | MEDIUM — verify URL sanitization |
| `gateInfo.title` / `gateInfo.message` | Server API response | string in AccessGate | Low |

**High-priority check: `link.url` in hyperlink overlays**
```jsx
<a href={link.url} target="_blank" rel="noopener noreferrer" ...>
```
- `link.url` comes from the server (sidecar extraction from PDF)
- Verify: does `link.url` allow `javascript:` protocol URLs?
- If not sanitized server-side: add `rel="noopener noreferrer"` (already present) AND check for `javascript:` prefix before rendering
- This is a MEDIUM priority finding if server does not sanitize
