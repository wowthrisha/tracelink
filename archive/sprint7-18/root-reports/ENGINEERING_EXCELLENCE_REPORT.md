# Engineering Excellence Report — Sprint V6.0 (Phase 10)

Scores reflect the repository's state *after* this sprint's fixes. Every score below 10/10 has a specific, cited reason and the smallest realistic next step — not a wishlist. Full evidence for every claim below is in the phase-specific reports (`ENGINEERING_GOVERNANCE.md`, `MODULE_BOUNDARIES_AND_CODE_QUALITY.md`, `UI_API_CONTRACT.md`, `SECURITY_GOVERNANCE.md`, `SCALABILITY_REVIEW.md`, `CONSISTENCY_MATRIX.md`, `REPOSITORY_HEALTH.md`).

| Dimension | Score | Why not higher | Smallest realistic improvement |
|---|---|---|---|
| **Architecture** | 9/10 | Layering is genuinely clean (zero cross-layer violations, verified by full import-graph check) and this sprint closed the two clearest business-logic-in-router duplications (`links.py`, `orgs.py`). What remains: `documents.py:upload_document` and `orgs.py:verify_custom_domain` still hold non-trivial business logic inline, and response-serialization is built via 6+ independently-invented per-router conventions rather than one shared pattern. | Extract `upload_document`'s quota-check and version-chain-resolution into `services/` — the split points are already identified in `MODULE_BOUNDARIES_AND_CODE_QUALITY.md`. |
| **Maintainability** | 7/10 | Real, cited duplication existed and much of it was fixed this sprint, but `AccessScreen.jsx` (900 lines, 53 `useState` calls, 3 unrelated feature domains) and `upload_document` (180 lines, 5+ separable concerns) remain large, multi-responsibility units that are harder to test and change safely than they should be. | Split `AccessScreen.jsx` into `LinksTab`/`FeedbackTab`/`AnnotationsTab` — natural boundaries already exist (they share only `docId`), making this the single highest-value, lowest-risk maintainability fix available. |
| **Readability** | 8/10 | Naming is consistent, the repo is genuinely clean of TODO/FIXME/console.log/debugger litter, and helper functions are well-named. Docked for magic strings/numbers (status strings, rate-limit literals, pagination defaults) repeated as bare literals instead of named constants across multiple files. | Centralize document-status strings (`"uploaded"/"processing"/"ready"/"error"`) into one constant, mirroring how `RETENTION_POLICIES` is already done correctly in `models/document.py` — a proven pattern already exists in the same file to copy. |
| **Security** | 8/10 | Strong, consistent scope/role enforcement after this sprint's fixes (a real org-member access-denial bug and a real API-key permission bypass both closed), solid webhook SSRF handling, uniform org-isolation checks across all 11 org endpoints. Docked for: AUTH-006 (session token in `localStorage`, a real XSS-exposure vector) remains fully deferred with only a plan, no code; and one permission question (`resolve_annotation`'s cross-viewer resolve capability) was left as an open decision rather than resolved either way. | Schedule the already-written `SECURITY_HARDENING_PLAN.md` Phase 0 as tracked, dedicated work — the plan exists in full, it just hasn't been executed. |
| **Scalability** | 7/10 | Indexing and caching are proactive and well-documented; the one download-heavy path (PDF export) is genuinely well-streamed. Docked for 5 confirmed unbounded list endpoints (`list_documents`, `list_links`, `storage_dashboard`, `list_members`, per-viewer reading sessions) that will become real problems at enterprise-account scale, none fixed this sprint because a backend-only pagination change without frontend consumption is a half-fix. | Add `limit`/`offset` to `list_documents` first (highest document-count accounts hit this first) *paired with* the frontend actually using it — a coordinated two-file change, not a backend-only patch. |
| **Consistency** | 6/10 | Lowest score outside Documentation. Two real, user-visible inconsistencies were fixed this sprint, but ~10 remain documented and open: the same "created at" field renders three different ways depending on screen, delete/revoke toasts vary between "success" and "info" severity for the same action class, empty states range from icon+CTA to bare gray text with no evident rule, and several create/edit modals bypass the shared `Modal` component entirely — losing focus-trap and Escape-to-close for keyboard users. | Unify date/time formatting onto the single existing `fmtDate()` helper (already created this sprint for a different consolidation) — the most-visible inconsistency, touches ~6 call sites, no new component needed. |
| **Documentation** | 5/10 | **The lowest score in this report.** `docs/release/` has 14 overlapping files including a certification document stamped v3.2.2 sitting next to peers stamped v8.1.0 — a five-major-version-stale document presented as current. Two competing CHANGELOGs exist (root, actively maintained; `docs/engineering/`, stuck at v3.2.1). No canonical database-schema document exists at all despite 27 migrations. The archive's own index (`archive/README.md`) points at six paths that don't exist. None of this was consolidated this sprint — each merge risks silently dropping real content from one side without the original authors confirming which is authoritative, which is a judgment call this sprint's time budget didn't allow doing carefully. | Retire `ZERO_DEFECT_CERTIFICATION.md` (unambiguously stale, no judgment call needed) and delete or fix `archive/README.md`'s dead pointers — the two lowest-risk, highest-clarity wins, doable without needing to adjudicate which of two overlapping *current* docs wins. |
| **Repository Structure** | 7/10 | Directory purpose/placement is sound overall (confirmed via a full directory-by-directory review this sprint) and one genuine hygiene issue (an empty nested `frontend/docs/` tree) was fixed. Docked for: 17 active sprint-report files sitting at repo root indefinitely rather than being archived once their work is committed, and a built artifact (`frontend/dist/app.bundle.js`) committed to git via an explicit `.gitignore` override. | Adopt the standing rule already written in `ENGINEERING_GOVERNANCE.md`: move a sprint's root-level reports into `archive/` once its changes are committed. Docked because documentation staleness actively works against a new engineer: `docs/api/API.md` is dated 2024-01 next to 2026-06/07 peers, and with 14 overlapping release docs there's no obvious single source of truth to point someone to. | Same fix as Documentation above — this dimension's score moves in lockstep with that one. |
| **Production Readiness** | 7/10 | This sprint found and fixed the single most consequential defect of the review: webhook deliveries were **silently non-functional in production** because the Celery worker never registered the delivery task. What keeps this below 8: AUTH-006 remains a real, known, unaddressed security exposure with only a plan (not a mitigation) in place, and the scalability findings above represent latent risk that hasn't yet caused an incident only because current account sizes haven't hit the unbounded-list ceiling. | Same as Security above — AUTH-006 Phase 0 is the single highest-leverage step available, fully planned, not yet scheduled as actual work. |

## What this sprint actually changed, in one paragraph

Found and fixed one severe production-breaking defect (webhooks silently never delivering), one real access-control bug (org members wrongly denied), one real permission-boundary bypass class already partially closed last sprint and reconfirmed clean, six audit-logging/consistency gaps, and five genuinely silent-or-misleading frontend failure modes that directly violated this sprint's own "never leave an action that silently fails" rule. Declined to implement roughly 30 additional real-but-lower-priority findings across architecture, scalability, consistency, and documentation — each is evidenced with file:line citations in its phase report, and each was left undone for a stated, specific reason (needs a product decision, needs coordinated multi-file/frontend-backend changes, needs dedicated follow-up time) rather than silently dropped. Full backend suite (1702 tests), frontend suite (13 tests), and build all pass with zero regressions introduced.
